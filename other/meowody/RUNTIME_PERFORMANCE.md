# 运行时性能优化

本次检查覆盖 App 每帧调度、协程、时间、网络、下载、资源、音频、UI、
事件、调试绘制、存档，以及 Cocos 控件和粒子更新路径。

已修改明确的重复开销：

- 协程、时间、网络、下载、资源、音频、UI 和调试命令复用更新快照。
  回调中新建任务仍在下一轮执行，取消未执行任务仍能阻止执行；
  finally 清空快照引用，避免完成的任务和 UI 被快照持续持有。
- 时间与下载在无工作时跳过调度；存档无待写分区时跳过集合复制，
  复用不可变的成功状态。
- 网络监听器只有通知状态变化时才复制。
- 音频仅在音量、暂停状态变化时调用播放器设置接口，仍逐帧检查播放完成。
- UI 复用排序快照及比较器，无待交付回调时不建列表；用目标 ZIndex
  替代每帧反复 toFront，顺序已正确时不移动 layer。
- 事件监听器在订阅变更时替换数组，emit 无需复制；保留同步递归通知、
  新监听器不参与当前通知、取消待通知监听器的语义。
- 调试性能图直接遍历采样队列，不再逐帧复制全部采样。

## 测量

`RuntimePerformanceCheck` 预热 20000 帧后测量 20000 帧，使用
ThreadMXBean 统计当前线程分配。测量包含时间、协程、网络、下载、音频
中心，不包含资源加载、UI、渲染、工作线程及实际平台音频。

| 场景 | 修改前分配 | 修改后分配 |
| --- | ---: | ---: |
| 空闲 | 920 字节/帧 | 约 0 字节/帧 |
| 1000 个常驻协程 | 4712 字节/帧 | 约 0 字节/帧 |

同机的一次记录：空闲约 0.79 → 0.04 微秒/帧；1000 协程约
2.64 → 1.59 微秒/帧。微基准耗时会受 JIT、GC 和系统负载影响，
这些数字不能当作游戏 FPS 或 GPU 渲染性能提升。

运行：`gradlew.bat :meowody:runtimePerformanceCheck :meowody:layoutCheck`。
新增检查包含协程清空与回调新增、重入保护、事件通知期间新增与清空、
音频状态变化和完成回调新建播放。

Java 编译、新增回归和布局检查通过。既有 FrameworkSelfTest 已执行到
本机 HTTP 服务初始化之前；网络/下载/资源后续检查受本机 JDK 的
`Unable to establish loopback connection` 阻断，沙箱外重试仍失败。

未改动批处理策略、粒子数学和绘制顺序；这些路径需要实际场景 CPU/GPU
采样后才能判断收益。本次保留每个节点已有的布局 Action 与逐帧动画行为。
